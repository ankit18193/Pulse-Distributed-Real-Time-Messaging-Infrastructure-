## 1. Problem Statement

Pulse has successfully completed Phases 1 through 10, establishing a distributed, multi-node, Redis-backed real-time messaging engine equipped with cluster pub/sub, Lua-powered presence tracking, Prometheus observability, embedded RouteX gateway integration, an operational Mission Control dashboard, and production-grade resilience hardening (CSWSH origin defense, token bucket rate limiting, atomic connection admission, room subscription bounds, graceful draining).

However, Pulse currently exists primarily as a standalone repository and application (`pulse-realtime`). Its entry point (`src/index.ts`) mixes application bootstrap logic with indiscriminate re-exports of internal classes (`MessageDispatcher`, `PresenceManager`, Lua script strings, `TokenBucket`, `HeartbeatManager`). An external software engineer wishing to add distributed real-time WebSocket capabilities to their Node.js or TypeScript application cannot cleanly `npm install @ankit18193/pulse` and instantiate a server with predictable, encapsulated APIs.

Phase 11 transforms Pulse into a premier, reusable NPM server package (`@ankit18193/pulse`) with pristine type definitions, strict information hiding, ergonomic configuration inheritance, a dedicated standalone runner, an isolated external consumer test harness, and exhaustive developer documentation.

## 2. Core Value & "What Makes This Cool"

1. **Instant Time-to-Hello-World (TTHW)**:
   A developer can install `@ankit18193/pulse` in any Node.js/TypeScript project and launch a fully functional, clustered real-time messaging server in fewer than 10 lines of code:
   ```typescript
   import { PulseServer } from "@ankit18193/pulse";

   const pulse = new PulseServer({ port: 8080 });
   await pulse.start();
   ```
2. **Zero Internal Leakage with Zero Core Rewrites**:
   The complex distributed machinery (Lua presence scripts, atomic admission gates, connection pools, sliding heartbeat sweepers) remains completely private. Application developers get a clean, expressive API surface without needing to navigate internal plumbing.
3. **Inherited Production Hardening**:
   Every security feature hardened in Phase 10—origin defense, inbound token buckets, connection bounding, safe draining, and production secret enforcement—is automatically active out-of-the-box with sensible defaults, protecting external applications without requiring security expertise.
4. **Verified Distribution via `npm pack`**:
   Rather than trusting internal monorepo symlinks, Phase 11 validates the exact packaged `.tgz` tarball inside an external test consumer application to guarantee third-party installation readiness.

## 3. Constraints & Explicit Non-Goals

### Non-Goals (Explicitly Out of Scope)
- ❌ **No Client SDK**: Phase 11 packages the **server** infrastructure. Client connections use standard WebSocket clients (`ws`, browser native `WebSocket`, etc.).
- ❌ **No Domain / Chat UI**: Pulse remains generic distributed real-time messaging infrastructure, not a specialized WhatsApp or Slack clone.
- ❌ **No Cloud Deployment / Domain Provisioning**: Infrastructure hosting is reserved for Phase 12.
- ❌ **No HTTPS / WSS Infrastructure**: TLS termination remains an edge gateway / reverse-proxy concern (or RouteX gateway).
- ❌ **No Bluetooth / Mesh / Offline Queuing**: Out of scope.
- ❌ **No Modification of Core Distributed Algorithms**: Do NOT rewrite messaging logic, heartbeat sweeps, or Redis Lua scripts merely to package the server.

### Constraints
- **Preserve Phase 10 Hardening**: Configuration must enforce production secret validation, origin validation, connection limits, and graceful shutdown.
- **Zero Test Regressions**: All 81 existing test suites (382+ tests) must remain 100% green.
- **Node.js Engine Target**: `>=20.0.0` with ESM (`"type": "module"`) and TypeScript `NodeNext` resolution.

---

## 4. Premises

1. **Clean Minimal Surface & Strict Encapsulation**: `@ankit18193/pulse` exposes only top-level server primitives (`PulseServer`, `PulseServerOptions`, `PulseConfig`, `loadConfig`, `Authenticator`, `OriginMatcher`, hooks, and public types). Internal classes (`ConnectionManager`, `MessageDispatcher`, `PresenceManager`, `IdempotencyManager`, Lua scripts) remain unexported.
2. **Zero Modification of Core Algorithms**: Packaging does not alter the underlying distributed messaging algorithms, presence tracking, or Redis pub/sub mechanics.
3. **Black-Box Distribution Testing**: Package validation requires running `npm pack`, installing the generated `.tgz` archive into an isolated external project, and verifying live WebSocket connectivity, room subscriptions, message exchange, and graceful shutdown.
4. **Decoupled Release Trigger**: Phase 11 builds, packs, and validates the artifact locally. Actual publishing to the public NPM registry is an intentional release decision.

## 5. Approaches Considered

### Approach A: Minimal Export Wrapper (Minimal Viable)
- **Summary**: Comment out internal re-exports from `src/index.ts`, keep self-executing bootstrap at the bottom of the file, rename package in `package.json`.
- **Trade-offs**: High risk of side-effects on import (e.g. `process.argv` checks triggering accidental boots or dangling process listeners), awkward type exports.
- **Decision**: Rejected.

### Approach B: Clean Public Surface with Dual Entry (Library + CLI) & Isolated Consumer Harness (Selected)
- **Summary**:
  - Separate library entry point (`src/index.ts`) from CLI standalone runner (`src/bin/pulse-server.ts`).
  - `src/index.ts` exports only intentional public APIs: `PulseServer`, `loadConfig`, `Authenticator`, `OriginMatcher`, `PulseServerHooks`, `PulseConfig`, `PulseServerOptions`, `PulseEventEnvelope`, `PulseMetricsRegistry`.
  - `PulseServer` accepts flexible `PulseServerOptions = Partial<PulseConfig>` and merges with `loadConfig(options)`.
  - `package.json` configured with `@ankit18193/pulse`, `"main": "dist/index.js"`, `"types": "dist/index.d.ts"`, explicit `"exports"` map, and `"files": ["dist", "README.md", "LICENSE"]`.
  - Isolated external consumer harness in `examples/minimal-consumer/` running end-to-end integration tests directly against the packed `.tgz`.
- **Trade-offs**: Requires clean separation of entry files and updating any internal tests that imported engine internals from root index instead of deep paths.
- **Decision**: **SELECTED**. Provides the cleanest developer ergonomics, zero side-effects, and absolute isolation.

### Approach C: Monorepo Package Split (Lateral / Advanced)
- **Summary**: Split repo into `@ankit18193/pulse-core` and `@ankit18193/pulse` using npm workspaces.
- **Trade-offs**: Unnecessary complexity, high blast radius on build scripts, CI, and existing 382 tests.
- **Decision**: Rejected. Violates the rule: "Do not rewrite the messaging engine merely to package it."

## 6. Architectural Specification

### 6.1 Package Metadata (`package.json`)
```json
{
  "name": "@ankit18193/pulse",
  "version": "0.3.0",
  "description": "Pulse — Distributed Real-Time Messaging Infrastructure Server",
  "type": "module",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./config": {
      "types": "./dist/config/index.d.ts",
      "import": "./dist/config/index.js"
    },
    "./types": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/types/index.js"
    },
    "./metrics": {
      "types": "./dist/metrics/index.d.ts",
      "import": "./dist/metrics/index.js"
    },
    "./package.json": "./package.json"
  },
  "bin": {
    "pulse-server": "dist/bin/pulse-server.js"
  },
  "files": [
    "dist",
    "README.md",
    "LICENSE"
  ]
}
```

### 6.2 Public API Surface (`src/index.ts`)
```typescript
// Core Server
export { PulseServer, type PulseServerHooks, type PulseServerDependencies } from './core/PulseServer.js';

// Configuration
export { loadConfig, type PulseConfig, type PulseServerOptions } from './config/index.js';

// Authentication & Utilities
export { Authenticator, type AuthResult } from './auth/Authenticator.js';
export { OriginMatcher } from './utils/OriginMatcher.js';
export { generateUUIDv7 } from './utils/uuidv7.js';

// Metrics & Observability
export { PulseMetricsRegistry, PrometheusSerializer } from './metrics/index.js';

// Public Protocol Event Types
export type {
  PulseEventEnvelope,
  EventType,
  AuthPayload,
  RoomJoinPayload,
  RoomLeavePayload,
  MessageSendPayload,
  MessageAckPayload,
  PresenceQueryPayload,
  PresenceUpdatePayload
} from './types/index.js';
```

### 6.3 Flexible `PulseServer` Constructor
The `PulseServer` constructor will accept:
```typescript
export type PulseServerOptions = Partial<PulseConfig>;

export class PulseServer {
  constructor(
    options: PulseServerOptions = {},
    hooks: PulseServerHooks = {},
    deps: PulseServerDependencies = {}
  ) {
    this.config = loadConfig(options);
    // ...
  }
}
```
This ensures developers can pass `{ port: 8080 }` directly without manually calling `loadConfig`, while retaining full environment variable fallback and Phase 10 validation.

### 6.4 Standalone CLI Runner (`src/bin/pulse-server.ts`)
A dedicated executable script that loads configuration, initializes `PulseServer`, binds signal handlers (`SIGINT`, `SIGTERM`), and gracefully handles unexpected process crashes.
```typescript
#!/usr/bin/env node
import { PulseServer, loadConfig } from '../index.js';
import { logger } from '../utils/logger.js';

// Graceful signal handlers and bootstrap
```

## 7. External Consumer Test Harness

To prove that the package works as an external consumer would experience it:
1. **Packaging Step**:
   - `npm run build` generates `dist/`
   - `npm pack` generates `ankit18193-pulse-0.3.0.tgz`
2. **Consumer Fixture** (`examples/minimal-consumer/`):
   - Standalone `package.json` with dependency: `"@ankit18193/pulse": "file:../../ankit18193-pulse-0.3.0.tgz"`
   - Consumer application (`server.ts` or `index.mjs`) importing `PulseServer` from `@ankit18193/pulse`.
3. **Automated Integration Test** (`tests/package/external-consumer.test.ts`):
   - Spawns consumer server process.
   - Connects two independent WebSocket clients using native `ws`.
   - Performs handshake, authentication, room join, bidirectional message broadcast, and ACK verification.
   - Validates `/health` and `/metrics` HTTP endpoints.
   - Sends `SIGTERM` and asserts graceful drain and zero-error process exit.

12. **Production Hardening & Security**: CSWSH origin defense, rate limiting, connection limits, and graceful shutdown.
